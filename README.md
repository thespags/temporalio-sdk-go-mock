# temporalio-sdk-go-mocks

[testify](https://github.com/stretchr/testify) mocks for the public interfaces of
[`go.temporal.io/sdk`](https://github.com/temporalio/sdk-go), generated with
[mockery v3](https://github.com/vektra/mockery).

## Why does this exist?

The SDK ships a `mocks` package. It was generated by mockery v1, patched by hand, and covers
about a dozen interfaces. Mockery v3 makes mocks much nicer (`NewClient(t)` wires up
`AssertExpectations` for you, typed `EXPECT()` helpers, and so on), so we
[sent a PR](https://github.com/temporalio/sdk-go/pull/2137). It was closed. The mocks still
needed to exist, so here we are, maintaining them ourselves.

## Usage

```
go get github.com/thespags/temporalio-sdk-go-mocks@latest
```

Tags mirror the `go.temporal.io/sdk` version the mocks were generated against.

There is one package per SDK package that has mockable interfaces, named the same: `client`,
`converter`, `interceptor`, `log`, `temporal`, `temporalnexus`, `tracing`, `worker` and `workflow`.
Import with an alias so it doesn't clash with the SDK package:

```go
import (
	"github.com/stretchr/testify/mock"
	"go.temporal.io/sdk/client"

	mockclient "github.com/thespags/temporalio-sdk-go-mocks/client"
)

func TestStartsWorkflow(t *testing.T) {
	run := mockclient.NewWorkflowRun(t) // expectations are asserted automatically on cleanup
	run.EXPECT().GetID().Return("wid")

	c := mockclient.NewClient(t)
	c.EXPECT().
		ExecuteWorkflow(mock.Anything, mock.Anything, "MyWorkflow", mock.Anything).
		Return(run, nil)

	var _ client.Client = c
	// ... code under test ...
}
```

### Migrating from `go.temporal.io/sdk/mocks`

- Swap the import. Struct names are the interface names (`Client`, `WorkflowRun`), not `Mock`-prefixed.
- `mocks.Value` is gone. Use `converter.EncodedValue`.
- Variadics are matched as one slice, as above. The old mocks spread them.
- Many more interfaces: everything exported by the SDK (`worker.Worker`, `workflow.Context`, `log.Logger`, ...).

### What is not here

These can't be mocked outside the SDK because their methods use SDK-internal types with no public alias.
They are excluded in `.mockery.yml`:

- `interceptor.ActivityOutboundInterceptor`
- `interceptor.ClientOutboundInterceptor`
- `interceptor.NexusOperationOutboundInterceptor`
- `worker.SlotReleaseInfo`

For the interceptors, embed the SDK's `...Base` type and override the methods you need.

`ClientOutboundInterceptor` and `SlotReleaseInfo` use types (`ClientPollWorkflowUpdateInput`/`Output`,
`SlotReleaseReason`) that the SDK doesn't export at all.

`ActivityOutboundInterceptor` and `NexusOperationOutboundInterceptor` use `internal.Client` in `GetClient`.
`client.Client` is a separate interface rather than an alias, so a mock returning it compiles but does **not**
satisfy the SDK interface. It is better to have no mock than one that can't be passed where an interceptor is expected.

Unexported interfaces are not mocked (only `temporalnexus.operationTokenI` needed excluding, because its mock didn't compile).

## How it stays current

Nobody should run mockery by hand.

1. Dependabot (`.github/dependabot.yml`) bumps `go.temporal.io/sdk` daily.
2. `.github/workflows/dependabot.yml` regenerates the mocks on that PR, pushes the result to the
   branch, re-runs CI, and turns on auto-merge.
3. `.github/workflows/ci.yml` (check name: `ci`) installs the tools with
   [mise-action](https://github.com/marketplace/actions/mise-action), runs `mise run mockery`, and fails if the
   committed mocks differ. Then it runs `go build ./...`. If an SDK change breaks the mocks, the PR sits red instead of merging.
4. `.github/workflows/release.yml` tags `main` with the SDK version.

To regenerate locally: `mise run mockery`

## How the generation works

The SDK declares most of its API in `go.temporal.io/sdk/internal` and re-exports it through type
aliases (`type StartWorkflowOptions = internal.StartWorkflowOptions`). Mockery renders the original
internal types, which nobody outside the SDK can import. Two things in `.mockery.yml` deal with that:

- `resolve-internal-aliases: true` makes mockery use the public alias wherever the output package
  can't import the original.
- `generate: false` on specific interfaces leaves out the ones with no public alias to use.

### Mockery fork

Neither `resolve-internal-aliases` nor `generate: false` working together with `all: true` is in a released
mockery yet. `go.mod` has a `replace` pointing mockery at a fork
([vektra/mockery#1189](https://github.com/vektra/mockery/pull/1189)). `go tool mockery` runs it, so CI
and local runs agree. Once that merges and releases, delete the `replace` line and bump the `tool` version.
The fork is pinned to a commit, so bump it by hand: Dependabot can't.
